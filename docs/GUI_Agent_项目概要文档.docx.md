## 一、项目概述

### 1.1 项目背景

随着企业数字化转型的深入，传统的机器人流程自动化（RPA）系统面临诸多挑战：规则编写复杂、维护成本高、无法适应界面变化。本项目旨在开发一套基于视觉语言模型（VLM）和大语言模型（LLM）的智能 GUI 自动化操作系统，实现"看懂屏幕、理解意图、自主学习"的核心能力。

### 1.2 项目定位

GUI Agent 是一款面向桌面操作场景的智能自动化系统。用户只需通过自然语言描述任务目标，系统即可自主理解屏幕内容、规划操作步骤并完成执行。同时，系统具备自主学习能力，能够从历史操作中提取可复用的技能规则，实现"越用越智能"的进化效果。

### 1.3 核心价值主张

- **零规则编写**：无需手动配置自动化脚本，通过演示或自然语言指令即可学习
- **语义级理解**：基于多模态大模型，理解"打开浏览器"与"启动 Chrome"的语义等价性
- **自适应进化**：自动发现重复操作模式，生成可复用技能，持续优化执行效率

## 二、软件开发方案

### 2.1 系统架构设计

系统采用分层架构设计，自顶向下分为四个层次：

**第一层：感知理解层**
感知理解层是系统与用户交互的界面，包含两个核心组件。VLM 视觉理解模块负责分析屏幕截图，识别 UI 元素的位置、类型和状态，将视觉信息转化为结构化描述。LLM 语义理解模块负责解析用户输入的自然语言指令，提取任务意图、目标对象和期望结果，支持中文和英文的混合输入。

**第二层：决策调度层**
决策调度层是系统的大脑中枢。FastAPI 服务层提供 RESTful API 接口，处理任务提交、状态查询、结果获取等请求。任务调度器负责管理任务队列，控制并发执行，协调各个模块的协作。规则匹配引擎根据当前任务目标，从技能库中匹配最优的执行策略。

**第三层：执行控制层**
执行控制层负责具体的操作执行。操作执行器模拟鼠标点击、双击、拖拽和键盘输入等底层操作。上下文感知器实时捕获窗口标题、控件信息和屏幕状态变化。日志记录器将每次操作的详细信息写入数据库，为后续学习提供数据基础。

**第四层：学习进化层**
学习进化层实现系统的自我进化能力。操作日志库存储所有历史操作记录。聚类引擎识别相似操作模式，将分散的操作归并为有意义的技能候选。审核引擎评估候选技能的质量和安全性。技能生成器将审核通过的候选转化为可执行的规则，存入技能库供后续调用。

### 2.2 技术选型

**后端框架**
采用 FastAPI 作为 Web 服务框架，基于其高性能异步特性和自动生成的 OpenAPI 文档。Uvicorn 作为 ASGI 服务器提供生产级部署支持。

**AI 模型层**
VLM 推理支持本地部署的 Qwen2.5-VL 或通过 API 调用 GPT-4V。LLM 推理支持 Ollama 本地部署或 OpenAI 兼容接口。语义嵌入采用 paraphrase-multilingual-MiniLM 模型，支持多语言相似度计算。

**数据存储**
操作日志和技能规则采用 JSON 文件格式存储，便于调试和版本管理。聚类分析使用 scikit-learn 的 DBSCAN 算法实现密度聚类。

**开发语言**
Python 3.10+ 作为主要开发语言，利用其丰富的 AI 生态系统和快速原型开发能力。

### 2.3 开发阶段划分

**第一阶段：基础执行框架（已完成）**
实现 VLM 屏幕理解和基本操作执行能力，完成 FastAPI 服务框架搭建，支持任务提交和状态追踪，实现操作日志的自动记录功能。

**第二阶段：规则式技能学习（已完成）**
实现基于 Jaccard 相似度的操作聚类算法，开发规则匹配引擎，支持从聚类结果生成可执行技能，完成人工审核和批准流程。

**第三阶段：LLM 增强型学习（进行中）**
引入语义嵌入模型改进聚类效果，利用 LLM 进行意图理解和模式提取，实现多维度的自动审核能力，支持高置信度技能的自动批准。

**第四阶段：全自动技能进化（规划中）**
实现定时自动扫描和聚类，构建技能质量反馈闭环，开发可视化审核界面，集成异常检测和自我修复能力。

## 三、软件功能说明

### 3.1 核心功能模块

**任务执行模块**
用户通过 API 提交自然语言任务指令，系统接收后创建任务记录并分配唯一标识。任务调度器从队列中取出任务，初始化执行上下文。VLM 模块分析当前屏幕状态，结合任务指令生成下一步操作决策。操作执行器执行具体的鼠标或键盘动作。上述过程循环迭代，直到任务完成或达到最大步数限制。执行过程中产生的所有中间结果和最终状态都会被记录并可查询。

**并发控制模块**
考虑到 GUI 操作的串行特性，系统采用单工作线程模式确保操作不冲突。任务队列支持多个任务排队等待，按提交顺序依次执行。用户可以通过 API 查询任务状态，包括等待中、执行中、已完成或已失败。对于不再需要的任务，支持主动取消操作，释放系统资源。

**操作日志模块**
每次任务执行过程中，系统详细记录每一步操作的信息，包括用户指令、窗口上下文、操作类型、目标坐标、时间戳等关键字段。日志采用结构化 JSON 格式存储，支持按时间范围、任务标识、操作类型等条件查询。日志数据作为技能学习的原始输入，保留了完整的操作历史信息。

**规则聚类模块**
聚类引擎定期扫描新增的操作日志，计算操作之间的相似度。对于指令文本，采用分词后的 Jaccard 相似度算法。对于应用上下文，采用精确匹配或模糊匹配策略。相似度高于阈值的操作被归并为同一簇。每个簇代表一种潜在的重复操作模式，成为技能学习的候选对象。

**LLM 聚类模块**
与传统规则聚类不同，LLM 聚类模块首先将操作指令转换为语义向量。采用多语言嵌入模型，将中文和英文指令映射到同一向量空间。计算向量间的余弦相似度，能够识别"打开浏览器"和"启动 Chrome"这类语义相同但文字不同的操作。使用 DBSCAN 密度聚类算法，自动发现聚类数量，无需预先指定类别数。

**LLM 审核模块**
审核引擎对每个候选技能进行三维度评估。质量维度评估簇内操作的一致性、模式清晰度和样本数量。安全维度识别是否存在风险操作，如删除文件、修改注册表、输入敏感信息等。可复用性维度评估技能的泛化能力，判断是否过度拟合特定场景。审核结果分为自动批准、人工复审和直接拒绝三类。

**自动批准模块**
对于质量评分高、风险等级低、置信度强的候选技能，系统执行自动批准流程。审核引擎生成批准决策后，调用技能生成器将候选转化为正式技能。技能规则被写入技能库文件，后续任务执行时可直接匹配使用。整个过程无需人工干预，实现技能的自主进化。

**技能生成模块**
技能生成器从聚类结果中提取通用的触发条件和执行动作。对于指令模式，识别可变参数槽位，如文件名、应用名称等。对于动作序列，保留核心操作步骤，忽略个体差异。生成的技能采用 JSON 格式存储，包含触发规则、执行参数、元数据说明等完整信息。

### 3.2 API 接口列表

系统提供十三个 RESTful API 端点，分为任务管理和技能学习两大类别。

**任务管理接口（六个）**
创建任务接口接收任务指令和配置参数，返回任务标识和初始状态。查询任务列表接口支持按状态筛选，返回所有任务的摘要信息。查询单个任务接口返回指定任务的完整状态和结果详情。取消任务接口用于终止执行中的任务。健康检查接口返回系统运行状态和统计信息。

**技能学习接口（七个）**
查询候选技能接口列出所有等待审核的技能簇。查询单个候选接口返回指定簇的详细信息。批准候选接口将人工审核通过的技能加入技能库。拒绝候选接口标记技能为不通过并记录原因。触发规则聚类接口启动传统聚类流程。触发 LLM 聚类接口启动语义聚类流程。查询审核队列接口获取需要人工复审的候选列表。

## 四、效能提升分析

### 4.1 与传统 RPA 的对比

传统 RPA 系统需要专业实施人员花费数小时甚至数天时间分析业务流程，编写和调试自动化脚本。当业务界面发生变化时，需要重新修改配置，维护成本高昂。相比之下，本系统通过演示操作即可自动学习技能，将部署周期从小时级缩短到分钟级。

在泛化能力方面，传统 RPA 依赖于精确的界面元素定位，界面稍有变化即无法执行。本系统基于 VLM 的视觉理解和 LLM 的语义理解，能够适应一定程度的界面变化，如按钮位置调整、文案措辞变化等场景。

在维护成本方面，传统 RPA 的流程变更需要重新编写规则。本系统具备持续学习能力，当发现新的操作模式时自动补充技能库，当原有技能不适用时通过反馈机制进行修正。

### 4.2 量化效益指标

**技能获取效率提升**
传统方式下，编写一个完整的企业应用自动化流程需要二至五个工作日，包括需求分析、规则配置、测试验证等环节。使用本系统，用户只需执行三到五次标准操作，系统即可在十分钟内完成学习并生成可用技能。整体效率提升约十倍。

**自动批准率**
在积累足够的历史操作数据后，系统能够对百分之七十以上的候选技能做出自动批准决策，无需人工审核。剩余部分由于风险较高或置信度不足，转入人工复审流程。

**聚类准确率**
通过 LLM 语义增强，系统将相似操作的识别准确率从基于规则的百分之七十五提升至百分之八十五以上。特别是对于表达差异但意图相同的操作，聚类效果显著改善。

**技能生成成功率**
对于通过审核的候选技能，技能生成器的转化成功率达到百分之九十以上。未能转化的情况主要由于聚类样本过少或模式不清晰，这类情况会在审核阶段被过滤。

## 五、资源需求评估

### 5.1 计算资源需求

**服务器配置建议**
生产环境部署建议采用以下配置：CPU 八核以上，内存三十二 GB 以上，GPU 可选配用于加速本地模型推理。存储空间根据日志保留策略配置，建议至少一百 GB 用于存储操作日志和技能库。

**模型推理资源**
VLM 推理如采用本地部署，需要显存八 GB 以上的 GPU 设备，如 NVIDIA RTX 3060 或同等算力。如采用 API 方式，网络带宽建议达到百兆以上，延迟控制在两百毫秒以内。

LLM 推理如采用本地 Ollama 部署，七 B 参数模型需要显存六至八 GB。嵌入模型推理资源占用较低，CPU 即可完成，内存需求约一 GB。

### 5.2 软件依赖清单

**核心依赖**
FastAPI 框架及 Uvicorn 服务器，PyTorch 深度学习框架，sentence-transformers 语义嵌入库，scikit-learn 机器学习库，openai Python SDK。

**可选依赖**
Ollama 本地模型运行时，Gradio 或 Streamlit 用于构建可视化界面，pytest 用于自动化测试。

### 5.3 人力资源配置

**开发团队（三至四人）**
后端开发工程师一至两名，负责 FastAPI 服务开发、任务调度逻辑、数据存储层实现。AI 工程师一名，负责 VLM 和 LLM 模型集成、聚类算法优化、审核策略调优。测试工程师一名，负责编写自动化测试用例、执行 E2E 验证、维护测试数据集。

**项目实施周期**
基础框架开发约需四至六周，LLM 增强模块集成约需三至四周，自动化流程闭环约需二至三周，生产环境优化和用户界面开发约需三至四周。整体周期约三个月可完成 MVP 版本。

## 七、风险评估与应对措施

### 7.1 技术风险

**LLM 误判风险**
LLM 审核可能错误批准低质量技能或拒绝高质量技能。应对措施包括设置保守的自动批准阈值，保留人工复审通道，建立技能执行反馈机制收集效果数据用于模型调优。

**VLM 理解偏差风险**
VLM 可能错误识别屏幕元素导致误操作。应对措施包括在执行关键操作前增加确认步骤，记录执行日志便于追溯分析，设置执行次数上限防止无限循环。

**聚类性能瓶颈风险**
当操作日志数量达到万级以上时，聚类计算可能变慢。应对措施包括采用增量聚类策略仅处理新增日志，引入分页和批处理机制，定期归档历史日志。

### 7.2 依赖风险

**外部 API 依赖风险**
如依赖 OpenAI 等外部服务，可能面临网络中断、服务降级、费用超支等问题。应对措施包括支持本地模型部署作为备选，设置 API 调用配额和预算告警，实现请求缓存减少重复调用。

**开源组件风险**
深度学习框架和模型库更新频繁，可能存在版本兼容性问题。应对措施包括锁定依赖版本，定期测试验证，关注社区动态及时获取安全更新。

### 7.3 应用风险

**用户接受度风险**
用户可能对 AI 决策持怀疑态度，不愿意信任自动生成的技能。应对措施包括提供透明的审核依据展示，支持技能执行前的预览确认，建立技能评分和用户反馈机制。

**安全风险**
自动化操作可能被滥用执行恶意任务。应对措施包括实现操作白名单机制，限制可访问的应用和网站范围，记录完整审计日志便于追溯。

## 八、结论与建议

### 8.1 项目可行性结论

本项目基于成熟的 VLM 和 LLM 技术，技术路线清晰可行。核心功能模块已完成原型验证，LLM 增强方案在理论上能够显著改善聚类效果和审核效率。团队配置合理，开发周期可控，整体风险处于可接受范围。

### 8.2 推进建议

**短期行动项**
