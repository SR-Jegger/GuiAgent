## 二、序列聚类功能实现

### 背景
一个指令可能包含多个操作步骤，例如：
- "任务名称一栏输入侦察任务" → [点击输入框, 输入文本]
- "输入http://localhost:3000/，进入无人作战指挥系统页面" → [点击地址栏, 输入网址, 按回车]

### 实现架构

```
┌─────────────────────────────────────────────────────────────┐
│  两个独立的聚类入口（需手动选择）                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 单操作聚类 scan_and_cluster()                           │
│     ├── 分组依据：instruction 相似性（Jaccard > 0.4）        │
│     ├── 每个 log = 1 个操作                                 │
│     └── 例：3次"双击打开Edge" → 1个cluster                  │
│                                                             │
│  2. 序列聚类 scan_and_cluster_sequences()                   │
│     ├── 分组依据：instruction_hash + task_name 完全相同      │
│     ├── 内部判断：                                          │
│     │   ├── 有连续step_id + 短间隔 → 拆成多个序列实例        │
│     │   └── 无连续step_id → 跳过（交给单操作聚类）           │
│     └── 例：3次"输入网址" → 3个序列实例 → 1个cluster         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 序列分组逻辑

```python
# 分组依据
key = (instruction_hash, task_name)

# 拆分判断
```

### 区分单操作与序列操作

```python
def _is_sequence_operation(logs):
    """
    判断是"序列操作"还是"单操作多次执行"

    序列操作：一次执行产生多个log，step_id连续
    单操作：每次执行产生一个log，可能执行多次
    """
    # Check 1: 只有1个log → 单操作
    if len(logs) == 1:
        return False

    # Check 2: 存在连续step_id + 短时间间隔 → 序列操作
    for log1, log2 in zip(logs, logs[1:]):
        if step2 == step1 + 1 and time_gap < 15:
            return True

    # Check 3: step_id范围 >= 2 且覆盖率 >= 50% → 序列操作
    if max_step - min_step >= 2 and coverage >= 0.5:
        return True

    return False
```

### 示例对比

| 场景 | step_ids | 时间间隔 | 判断 |
|-----|----------|---------|------|
| 双击打开Edge (执行3次) | [1, 1, 1] | 每次间隔 > 1分钟 | **单操作** |
| 输入网址进入系统 | [4, 5, 6, 4, 5, 6] | 组内间隔 < 10秒 | **序列操作** |
| 点击确认按钮 (执行5次) | [3, 3, 3, 3, 3] | 间隔 > 30秒 | **单操作** |

## 三、Pattern 提取逻辑改进

### 问题修复

| 问题 | 原因 | 解决方案 |
|-----|------|---------|
| Pattern 含 `\` 导致匹配失败 | `re.escape()` 转义了空格 | 自定义 `_escape_for_regex()`，只转义正则特殊字符 |
| 执行时输出 `{{content}}` | pattern 无捕获组，action 用了错误变量 | pattern 添加 `(.*)` 捕获组，action 用 `{{match_group_1}}` |
| 固定内容被参数化 | 未检查所有样本是否相同 | 检查 type text 是否全部相同，相同则用固定值 |

### Pattern 生成规则

```
输入: instructions = ["任务名称一栏输入 侦察任务01", "任务名称一栏输入 打击任务01", ...]

Step 1: 去重
Step 2: 单条指令 → 直接返回 escape(指令)
Step 3: 找最长公共前缀 prefix
Step 4: 找最长公共后缀 suffix（可选）
Step 5: 提取变量部分示例 variable_examples
Step 6: 生成带捕获组的 pattern

输出规则：
├── 有 prefix + suffix → {prefix}(.*){suffix}
├── 只有 prefix       → {prefix}(.*)
├── 只有 suffix       → (.*){suffix}
├── 无公共部分        → (.*)
└── 单条指令          → escape(指令)  # 无捕获组
```

### 正则转义规则

```python
def _escape_for_regex(text: str) -> str:
    # 只转义正则特殊字符，不转义空格
    special_chars = r'.*+?^${}()|[]\'

# 示例
"任务名称一栏输入" → "任务名称一栏输入"  # 无变化
"file.txt" → "file\.txt"  # 点号转义
```

### 与执行流程的关系

```
Pattern: "任务名称一栏输入 (.*)"
         ↓ 正则匹配
指令: "任务名称一栏输入 测试任务A"
         ↓ 捕获组提取
match_group_1 = "测试任务A"
         ↓ action 替换
type action: text = "{{match_group_1}}" → "测试任务A"
```

### 4.1 单操作聚类 actions 重复

**问题**：`"双击打开Edge Dev浏览器"` 技能的 actions 包含 3 个重复的 double_click。

**原因**：`_generate_actions()` 把聚类中所有操作的 action 都添加进来了。

**解决方案**：新增 `_generate_single_operation_action()`，只生成一个代表性 action，并对坐标取平均值。

```python
def _generate_single_operation_action(sample_actions):
    # 只取第一个作为模板
    # 对 click 类型，平均所有样本的坐标
    avg_x = sum(c[0] for c in coords) / len(coords)
    avg_y = sum(c[1] for c in coords) / len(coords)
    return [{"type": "double_click", "coordinate": [avg_x, avg_y]}]
```

### 4.2 候选技能界面不刷新

**问题**：前端候选技能界面没有实时反映 `operation_clusters.json` 的内容。

**原因**：`get_candidates()` 使用内存数据，不重新读取文件。

**解决方案**：每次调用时重新读取文件。

```python
def get_candidates(self):
    # 重新读取文件同步
    self.clusters = self._load_clusters()
    return [c for c in self.clusters.get("clusters", [])
            if c.get("status") == "candidate"]
```

### 4.3 Rejected 后无法重新聚类

**问题**：拒绝某个候选后，再次遇到类似操作时无法重新生成候选。

**原因**：收集已聚类 ID 时包含了 rejected 状态的 cluster。

**解决方案**：
1. 收集已聚类 ID 时排除 rejected 状态
