● 两轮合起来完成了方案一（数字标识法）+ UI 纠正展示，处理 ASR 语音识别的同音不同字问题。

  第一轮：数字优先匹配（dispatcher 命中）
  - 在 _try_cache_dispatch 前置数字优先逻辑：从指令抓 \d{2,} 数字段，在 cache 里找 target_id 的数字部分匹配
  - 解决核心痛点：ASR 把"剑发"识别成"建发"时，汉字子串匹配会 miss，但数字"8686"识别准确，通过数字仍能命中"剑发-8686"这条链
  - 多条命中时退化到子串匹配用汉字消歧，platform_id（如"206"）不误触发

  第二轮：UI 纠正展示（让用户看到准确文本）
  - 把数字优先匹配抽成独立函数 find_chain_by_number（service 和卡片层共用）
  - 新增 correct_target_id_homophone：命中后用 cache 真实 target_id 替换指令里的同音汉字部分（"打击建发8686" -> "打击剑发8686"）
  - 卡片层在 ASR 录音结束（手动停止 + 静音触发两条路径）调用纠正，写回 text_input 文本框和 countdown_hint 标签，让用户在提交前就看到纠正后的准确文本
  - 保守策略避免误替换：操作动词（"打击8686"不改）、无操作动词边界 case（"剑发8686"不改）、含短横（"打击剑发-8686"不改）
